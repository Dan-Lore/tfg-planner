# Спецификация продукта

> **Статус:** черновик v0.4.2 · живой документ  
> **Последнее обновление:** 2026-07-06

## 1. Видение

Веб-сайт для проектирования **производственных мнемосхем** под модпак [TerraFirmaGreg-Modern](https://github.com/TerraFirmaGreg-Team/Modpack-Modern).

Пользователь визуально собирает линии из механизмов, настраивает машины вручную, видит потоки материалов и может масштабировать производство. Данные рецептов соответствуют конкретной версии модпака и **извлекаются парсером** из репозитория модпака.

**Референс по UX расчётов:** [Factorio Calculator](https://kirkmcdonald.github.io/) (см. [inspiration.md](inspiration.md)).

**Недоделки без заглушек в коде:** [kanban.md](kanban.md).

## 3. Функциональные требования

### 3.1. Парсер и загрузка версий модпака

- **Парсер Modpack-Modern** — обязательный компонент; извлекает pack data из [репозитория TFG](https://github.com/TerraFirmaGreg-Team/Modpack-Modern) (KubeJS, конфиги, lock-файл). Детали: [parser.md](parser.md).
- Отдельное **меню «Версии»** (не смешивать с редактором схем).
- Пользователь выбирает версию модпака (например `0.12.8`).
- Приложение подгружает **нормализованный JSON-бандл** для этой версии.

**Критерии приёмки:**

- [x] CLI/CI собирает pack data для выбранного тега релиза.
- [ ] (P2) Периодическое обновление и мониторинг версий — **K-009 blocked** (ждёт спецуказания).
- [x] Список доступных версий отображается в меню.
- [x] После выбора версии редактор использует только её данные.
- [x] При смене версии — предупреждение, если схема несовместима (`ConfirmDialog`, import/switch pack).
- [x] Отчёт сборки (`build-report.json`) фиксирует непокрытые скрипты без silent-fail.

### 3.2. Редактор мнемосхем

- **Лист (холст):** свободное размещение узлов-механизмов.
- **Узел** — тип машины + выбранный рецепт + **ручные** параметры (overclock, `machineCount`, …); либо **`custom_machine`** — произвольные входы/выходы без рецепта pack (см. [custom-machine-nodes.md](custom-machine-nodes.md)).
- **Связь** — направленное соединение; передаёт поток предметов/жидкостей.
- Составление **производственных линий** из последовательных и параллельных участков.
- **История действий:** отмена и повтор операций на холсте.
- **Выделение:** ЛКМ drag на пустом холсте — рамка выделения; направление drag задаёт режим: слева→направо — только узлы целиком внутри рамки (сплошная синяя); справа→налево — пересекающиеся (пунктирная зелёная); Shift+ЛКМ — добавить к выделению.
- **Панорама:** ПКМ drag на холсте — перемещение вида (порты: ПКМ click — контекстное меню).
- **Подсказка управления:** кнопка «?» с перечнем горячих клавиш (i18n).

**Горячие клавиши (MVP):**

| Действие | Windows / Linux | macOS (доп.) |
|----------|-----------------|--------------|
| Отменить | **Ctrl+Z** | Cmd+Z |
| Повторить | **Ctrl+Y** | Cmd+Shift+Z |

Отменяются: добавление/удаление узлов и связей, перемещение, дублирование, изменение рецепта и параметров машины, закрепление потока на ребре (`edgeConstraints`).

**Критерии приёмки:**

- [x] Добавление механизма из каталога версии.
- [x] Соединение выхода одного узла со входом другого (валидация совместимости).
- [x] Визуализация скоростей на связях после расчёта.
- [x] На узле отображается `machineCount` (целое количество машин, ≥ 1).
- [x] Ctrl+Z / Ctrl+Y работают в редакторе; стек undo не ломается при пересчёте потоков.
- [x] ЛКМ — рамка выделения (направленная: window/crossing); ПКМ drag — панорама; подсказка «?».

### 3.3. Калькулятор потоков (двусторонний, только продукты)

Расчёт касается **продуктов** (предметы, жидкости). Количество машин на узле — **целое число** (`machineCount`).

| Направление | Поведение |
|-------------|-----------|
| От цели | Пользователь задаёт «хочу N единиц/сек» на выходе → пересчёт потоков и **требуемых** `machineCount` по графу |
| От участка | Пользователь меняет скорость на связи / входе / выходе → **вся схема** пересчитывается согласованно |
| Топология | Новые узлы на холсте **не** создаются автоматически (кроме ручного режима A) |
| `machineCount` | Может задаваться вручную **или** обновляться калькулятором в режиме C после округления (§3.5.1) |

**Критерии приёмки:**

- [x] Любое изменение `machineCount`, закрепления потока на ребре или топологии триггерит полный пересчёт.
- [x] Потоки согласованы на всех рёбрах; byproducts учтены (sign-off `rebra-rhenium-loop.tfgp`, K-002).
- [x] `machineCount` на узлах всегда целое ≥ 1 после пересчёта.
- [x] Unit-тесты на линейные, разветвлённые цепочки и дробные множители с округлением.
- [x] Проверка схемы: баланс продуктов в циклах (SCC), катализатор, структурные предупреждения (`target_not_output`, `disconnected_output`).
- [x] **Bootstrap циклов:** петля заводится через главное ребро `intermediate_buffer` → кольцо (продукт буфера); `start_buffer` — внешнее питание (не балансируется как дефицит петли). Seed-поток на ребре; подпись % воспроизводства и баланса (deficit / stable + объём буфера / surplus); предупреждения `cycle_product_*` только для seed-продукта (K-023, sign-off `rebra-rhenium-loop.tfgp`). **Баланс seed-продукта в SCC:** производство и потребление в **items/s** (effective out / port demand машин; `intermediate_buffer` не входит в сумму); **попытки/с** = expected÷(chance/10000) на портах с chance; воспроизводство = попытки produce÷попытки consume×100 (≈100% в замкнутой петле катализатора); net = expected produce−expected consume. **Ёмкость буфера катализатора (1 ч, 99%):** n = attempts/s×3600, μ=n·p, σ=√(n·p·(1−p)), capacity=⌈μ+2.33σ⌉ (+ часовой дефицит при expected net&lt;0). Инспектор seed-ребра: петля, попытки produce/s, expected consume/s, воспроизводство, режим (самодостаточный / deficit / surplus), рекомендуемая ёмкость с tooltip расчёта; без дубля «Поток (источник/приёмник)».
- [x] **Узкое место:** при загрузке узла &lt; 100% на карточке машины и в инспекторе показывается краткая причина («мало на входе» / «упор на выходе» + продукт); tooltip — порт, фактический и требуемый поток. «Мало на входе» — только когда `maxLoad ≈ throughput` (входы — лимит). «Упор на выходе» — порт с насыщенным машинным потребителем (`nodePortOutConsumerLoad`); сток/end buffer не считается.

### 3.4. Энергия (EU/t)

- **Цель:** отображать энергопотребление на схеме (узел, линия, группа).
- **Модель pack data:** `Recipe.energy` = `EnergyStack` на **минимальном tier** рецепта: `{ minVoltageTier, voltage, amperage }`; `EU/t = voltage × amperage` на min tier; `amperage` **статичен** (не зависит от tier узла и overclock); `durationTicks` — время на min tier.
- **Узел схемы:** `voltageTier` (tier машины / energy hatch, ≥ min tier рецепта); `overclock` ускоряет рецепт (сокращает duration и повышает продуктовые потоки), **не** меняет EU/t. Multiblock energy hatch count / parallel — **K-012 `blocked`** (ждёт спецуказания; не выводить из `amperage`).
- **GT voltage overclock:** при tier узла выше min tier — duration ÷ 2^Δtier, EU/t = `GTValues.V[nodeTier] × amperage` (amperage из pack).
- **Singleblock:** в pack data `amperage ≤ 1` на min tier; tier узла может быть выше min tier рецепта.
- **Запрещено:** показывать фиктивные значения (0, «—», placeholder), если данных нет.
- Энергия в pack data присутствует **только** когда парсер её достоверно извлёк.

**Критерии приёмки (по мере закрытия подзадач K-003):**

- [x] EU/t на узле — только при `recipe.energy` в pack data.
- [x] Tier picker на узле (≥ min tier); overclock не влияет на EU/t.
- [x] Суммарное потребление **выделенных** узлов (`src/lib/selection-energy.ts`).
- [ ] Суммарное потребление линии / группы — **K-012 `blocked`**
- [ ] Непокрытые рецепты остаются в kanban, не в UI (~0.3% без energy в 0.12.8).

### 3.5. Масштабирование линий

**MVP:** пользователь задаёт топологию и **`machineCount`** на узлах; калькулятор пересчитывает продуктовые потоки. Опционально — закрепление потока на ребре (`edgeConstraints`, K-002). Замкнутые циклы (SCC) — cycle bootstrap на seed-ребре (K-023).

#### Режим A — ручное повторение линии

Пользователь **сам копирует** фрагмент схемы: дублирует узлы и связи на холсте (copy/paste или аналог), расставляет параллельные ветки, при необходимости объединяет потоки.

- Калькулятор пересчитывает потоки по фактической топологии.
- Автоматическое умножение узлов **не** выполняется.

#### Округление `machineCount`

**Инвариант:** `machineCount ∈ ℤ`, `machineCount ≥ 1`.

При будущем расчёте целевой скорости из тулбара (K-024) — `ceil(ideal)`, минимум 1, затем полный пересчёт потоков.

#### Общее

| Правило | Описание |
|---------|----------|
| Пересчёт | Правка топологии, `machineCount`, `edgeConstraints` → полный пересчёт продуктовых потоков |
| Топология | Автодобавление/автоудаление **узлов** на холсте запрещено |
| `machineCount` | Задаётся вручную в инспекторе; всегда целое |
| Undo | Изменения графа и параметров — **Ctrl+Z** / **Ctrl+Y** |

**Критерии приёмки:**

- [x] Режим A: дублирование узлов/связей пользователем + корректный пересчёт потоков.
- [x] Ручной `machineCount` и `edgeConstraints` → согласованные потоки на рёбрах.
- [x] SCC: cycle bootstrap без целевых скоростей в `.tfgp`.
- [x] Отмена/повтор через Ctrl+Z / Ctrl+Y.
